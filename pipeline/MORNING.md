# Village Morning: a first day at home

This is a second selectable journey, implemented as one small slice for review with the user. Choose **New journey → Village Morning → Begin new journey**. Kindle Hollow remains a separate journey with its original map, code notebook, controls and saved progress.

## What plays now

The opening fade leads to the boy standing beside his bed. Hotaru, a tiny glowing orb with four fluttering wings, follows the boy and speaks through the same visual novel conversation scene as the residents. Her portrait is a cute black-haired fairy with a composed expression; she introduces his notebook through a linear explanation. Before learning to speak, the player has no reply/topic menu. The final dialogue page automatically opens /00. This is a prose waking moment, not a new sleeping/waking sprite animation. The unique 12×11 room has two curtained windows, panelled walls and a framed botanical print, oak flooring, a rug, patchwork bed, wardrobe, writing desk and notebook, books, washstand, chair and bedside stool. The central bed sits between the windows; desk and washstand share the side wall, and the chair sits beside the bookcase. Its seven furniture instances reuse adopted artwork. The approved boy and camera are unchanged.

**Field Notes / 00 — Saying Hello** comes first. A print block with editable text compiles to `def program(world): print("Hello, Hotaru!")`; the Python tab has a separate draft. Test code runs the actual WASI program, opens the generated source beneath the block and replays executed lines. A separate foreground voice window displays the words when the print line runs. **Speak** applies that same speech proposal. A greeting that includes Hotaru’s name completes `say-hello` and automatically starts Hotaru’s First Steps introduction. Its final page opens /01, with no separate notebook choice or second Continue in the greeting lesson. Test remains a preview until Speak commits it. Other text can be spoken, but does not satisfy the greeting goal or advance the tutorial. Optional replies unlock after learning to speak. The unlock uses sticky quest completion, so Undo can remove the utterance without removing what the player learned. Hello is case-insensitive and accepts hello, hi, hey or good morning with the name Hotaru.

**Field Notes / 01 — Your first steps** (**Make the keys your own**) asks the player to connect keys to four movement directions. A stitched side notebook opens on the right without dimming the room; the camera makes space for the character. Quest progress and the next instruction sit in a translucent window on the left. These are shared interface patterns with Kindle Hollow, including quest completion in the left window.

**Blocks** now reads like numbered event code: `when key W:`, then an indented expression such as `y += 1`. Each block edits a key, axis/operator and amount from 0–4. W begins as a one-step example; the other amounts begin at zero. **See Python** shows the real generated program. It starts each event at `x = y = 0`, performs the arithmetic, then records `world.controls.bind_move(key, x, y)`. **Python** offers an editable arithmetic starter. These are separate remembered drafts, not a freely draggable block language.

**>** on a block compiles and tests only that event, even while other rows are unfinished. Section tests never produce an applicable preview. **Test code** compiles all the blocks or runs the handwritten source through the existing WASI worker. Both produce the same bounded diagnostic traces and feed the same separate foreground test window: a larger view of a copy of the current room, the animated boy and numbered targets. Try 0 to see no movement, 1 for a single step, and 3 to overshoot. The first target is green, excess cells red, and furniture/edges stop animation at the last safe cell. The window sits over the lower-right free world area beside the notebook and does not change camera reservation. Successful event blocks turn green with a Passed badge; failed events turn red with Fix/Blocked. Editing returns them to Untested. Click a key button to replay it; focus the mini-scene to use physical keys. Syntax/runtime errors mark the Python line; invalid movement explains the fault and highlights its event block. A bad program cannot be applied.

The compact desktop layout keeps the drawer width, compresses events into code rows and gives the execution pane the remaining vertical space. Manual Python and See Python use the main editor with shared execution highlighting. The code font and global interface scale remain independent.

Both lessons use bounded execution evidence recorded by `sys.settrace` inside the WASI process. The notebook highlights actual source lines, displays small x/y/key/message values, and supports Replay, Pause and Next line. A movement command triggers its mini-room replay when the corresponding executed call is reached. Blocks show a small Python pane automatically while testing; handwritten Python highlights the original editor. Runtime errors retain the path to the failing line; syntax errors mark the line without pretending anything ran. Evidence is limited to the first 96 events, validated as plain data at the boundary and trimmed to stay within the existing result budget. It cannot become a world command. Testing does not execute again during visual replay.

The test viewport cannot change the real player, world, saved state or practice. **Apply** installs the same validated unit-step proposal. Source edits, block edits, mode changes, real movement, Undo, reset, closing and travel invalidate old proposals; edits and closing clear replays too. Undo restores the previous applied map and keeps the drafts. **Continue · try my keys** returns to the room after all four directions are applied. **Finish · back to the room** is available after practice; E, Esc and the close button also remain. Take one successful bound-key step in each real direction. Blocked attempts, click routes and the test bench do not count. E opens the notebook again.

The movement quest completes after four distinct directions are mapped and tried. Click walking and the exit then become available. One outward input from the door sill leads to a 64×72 village with the retained Concept Cottage, Rootward Square and an enterable town hall. There are no new residents or further quests. The frame is aligned to the exit cell, its jambs block movement, and the south cutaway is a boundary. The actual floor/base geometry ends at the sill. The cottage’s catalog entrance reserves an extra exterior landing cell. Approaching the landing is an ordinary walking step. The next inward input toward the frame opens the leaf and fades from the current safe cell. Leaving returns to the landing. Indoor exit still fades from the sill. Return home through the ordinary door flow. Room memory and quest state persist; voice/greeting state, applied controls and the separate greeting/movement drafts follow the player indoors and out. Reset clears room objects/memory while keeping voice, learned controls/practice and sticky quest completion.

Speech is exactly `{"op":"say","target":"hotaru","text":"Hello, Hotaru!"}`: current-area companion target, 1–160 characters, no range/occupancy effect. It records a voice and greeting flag on the detached candidate. Other levels reject it and keep ordinary print as stdout. Undo restores speech with the other program effects.

The arithmetic command is exactly `{"op":"bind_key","target":"player","key":"W","delta":[0,1]}`. The existing four-field `direction: "north"` form remains compatible. Its target is the current player's input map; recording a binding does not move the player or create a Python callback. Only areas with `movement_lesson: true` accept it. Supported physical keys are W/A/S/D and UP/LEFT/DOWN/RIGHT, with at most eight installed bindings. Applied movement must be one cardinal unit. Zero, diagonal and excessive deltas reject the entire batch. Diagnostic examples accept whole deltas from -4 to 4, inspect at most the command budget, keep at most eight key traces and never cross blocked passages. Malformed or unbounded values reach neither the world nor viewport.

Guided rows require unique keys. Multiple keys may share a direction, but completion requires all four. Rebinding to a different direction clears practice so the installed layout is tried; running an unchanged map preserves practice. For repeated valid bindings within a Python program, the mini-scene uses the last instruction for that key. An earlier invalid instruction remains visible because it prevents applying the whole batch.

Actual movement still checks the small foot footprint, furniture, neighbors and support in `LabWorld`. A recorded practice direction requires a successful step whose key matches its currently installed binding. Python executes during Preview in the bounded worker/WASI runner, never on a key press or in the engine process. Legacy areas reject binding commands and retain their normal input.

## Saves and adding another concept

`kindle_hollow.save.json` remains Kindle Hollow's save. Village Morning uses `kindle_hollow.save.village-morning.json`, in the same project-specific user directory. The saved editor also includes each block’s `amounts`; older drafts without amounts migrate to one for mapped rows and zero for incomplete rows. The profile remembers `last_level` alongside the shared name; shared settings remain separate. Starting over deletes only the selected journey. Room saves retain the existing travel/version format, with optional `controls`, `movement_used`, `movement_editor`, `greeting_editor`, `spoken` and `hotaru_greeted` fields; older saves without them load with empty maps/drafts.

Room version 3 removes the candle and the two decorative boot blocks after version 2 rearranged the furniture; an older player position now occupied by it resumes at the clear spawn while preserving saved progress. Known older room saves on the former front strip and cottage saves at newly corrected wall edges recover to a safe approach while preserving their other state. `test/test_doorway_boundaries.gd` covers these repairs, shared frame geometry and rotated/scaled wall collision.

Register future journey cards in `content/levels/catalog.json`, with a unique id, root `area` and optional `opening_house`. Author the actual map under `content/areas/` and register room overrides if needed. This is journey selection, not general travel between outdoor regions.

## Rootward Square

The [illustrated village art pass](reviews/2026-10-26-illustrated-village.md) updates Village Morning to version 5. Its presentation settings live in `pipeline/world-catalog.json`: `square-lamppost` for post lamps, `painted-cottage` for the comparison cottage, and `painted-oak` for broad `hearth-oak` trees. The underlying cottage ids, tree positions, door contracts, root radii and saved room instances remain the same. Two low solid fences leave an opening at [14,20], and a garden lamp stands at [13,23.5]. The hall’s flowerpots move clear of the new limestone lamp planters. These are authored props/lamps in the area document, not renderer-created map placements. No new quest or movement rule is introduced.

`village-morning.json` version 3 expands the map to 64×72 cells while preserving the home, its return landing and the southern lane. A broad cobbled loop surrounds Rootward at [32,36]; the town hall stands at [32,59], reached through its forecourt. The square has seats at human scale, planters, six ordinary post lamps and room for future plots. The namesake tree is a new adopted Blender master, roughly 24 m high and 22 m across, with an 8.6 m solid radius covering roots and the ward ring. The complete tree remains in the adopted source/export, but gameplay always hides its spreading crown/boughs and softly fades the upper trunk and chains from 8 to 10 m. This trunk cutaway keeps the town visible and removes the canopy shadow. Thirty jewel lanterns, nine festoons, surface-fitted gold root seams, ward stones and 84 animated wisps give it a mystical presence. `RootwardPresence` reads its light/wisp anchors from the model, renders three instanced batches and uses three shadowless local lights on lower lanterns. These effects never affect collision or progression.

The town hall has limestone courses, cream half-timber panels, teal shingles, warm windows, arched double doors, a brass clock, an open bronze-bell belfry, banners, nameboard and notices. Both door leaves use the common door adapter. Its override in `content/interiors/catalog.json` opens `morning-town-hall-room.json`, a separate saved 16×15 civic room with a clear central aisle, public benches, clerk’s desk, council table and archives. `art/town_hall_room.gd` owns the cutaway shell. The bedroom remains its own instance. No new quests, NPCs or runtime art services were added.

`test/test_landmarks.gd` checks square/door/furnishing reachability, solid trunk/root occupancy, old-lane save preservation, both hinges, cosmetic animation isolation and independent council/bedroom state through travel and Continue. Its graphical run captures both the normal gameplay scale and an explicitly review-only wide overview; it does not change the game’s approved camera settings.

The [trunk cutaway review](reviews/2026-10-26-rootward-trunk-cutaway.md) records the current view. This is permanent rendering, independent of player distance, zoom, collision and saves.
